# How the prototype relates to Mozilla's fellowship call

This page connects the public prototype to the [official 2027–2028 Fellowship request for proposals](https://assets.mofoprod.net/network/documents/PUBLIC_2027_2028_Fellowship_RFP-3.pdf) and [fellowship page](https://www.mozillafoundation.org/en/what-we-do/grantmaking/fellowship/2027-call-for-applications/). The RFP is the source for the fellowship and host requirements. This page is an evidence map, not an application.

| What Mozilla asks applicants to consider | What MindCommons can show now                                                                                                    | What remains unknown or future work                                                                                                     |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Give people meaningful influence over AI | The demo checks a fictional community rule and separate individual permissions before a fixed task.                              | People affected must define real authority and how to object or appeal. Demo roles are not verified identities.                         |
| Build open, useful infrastructure        | Public source code, a live demo, tests, agreement format and future-design page are available.                                   | The approach needs outside review, ongoing maintenance and community direction.                                                         |
| Address who benefits                     | A fictional benefit condition can block a research task until the team accepts it.                                               | Communities must decide what benefits matter and how responsibility and evidence work. No real benefit is claimed.                      |
| Respond to SRHIN's host challenge        | The project explores governance, permissions, privacy and benefits in an AI research scenario related to mental-health data.     | No SRHIN partnership, endorsement or participant feedback exists. Any future work depends on an authorized relationship and safeguards. |
| Show ability to carry out technical work | A working server-side rule check, bounded AI task, session receipt, automated tests and open-source repository can be inspected. | The prototype is not a patient-data platform, clinical tool or independent security certification.                                      |
| Explain public benefit and lasting value | Apache-2.0 code and documentation can be reused by others.                                                                       | A long-term maintainer and sustainability plan still need agreement.                                                                    |
| Explain who needs the work and why       | The public RFP describes the host challenge; Wellcome and SRHIN have also published related GENSCORE and co-design materials.    | These sources do not show demand for MindCommons. The project has no users or community validation evidence.                            |
| Respect applicant voice and AI-use rules | This repository contains technical evidence and planning notes, not personal application answers.                                | The applicant must write and submit personal responses in their own voice and disclose assistance accurately.                           |

The RFP's SRHIN challenge appears on page 7. It describes the host's stated challenge; it is not proof that MindCommons has been endorsed or adopted. Check the official RFP and application page for current program details.
