# Reviewer guide

**Live demo:** <https://mindcommons-mozilla-demo.bepoadewale1.workers.dev/>. The demo uses fictional community records and synthetic research material. It is a technical prototype, not a community pilot or clinical product. A separate static future-product visualization is available at <https://bepoadewale.github.io/mindcommons/>; it has no API or AI execution.

The live backend has completed a real model call, but the first reviewed response had an empty visible answer because the model spent its bounded output on reasoning. A documented model setting to disable reasoning is on the current feature branch and is not yet deployed. The currently deployed page should therefore not be treated as showing a useful final model result until that change is merged and verified.

For the intended live journey, choose **Explore the demo**, approve the fictional proposal, switch the demo seat to Researcher, and run the fixed “Community wellbeing research” evaluation. The API checks the active policy and the separate fictional individual permission, then calls Cloudflare Workers AI with a small synthetic corpus. Choose **Commercial advertising** and run again; the server denies it before model inference. Reload the page to inspect the decision in recent activity. The benefit commitment is hypothetical, with no delivery evidence claimed. A final browser recording will be linked from the README after its public artifact is verified.

The page identifies implemented and proposed capabilities. The demo role selector switches fictional seats in an isolated visitor session; these roles are not authenticated identities. The server-side checks demonstrate that policy and permission records affect the requested action, not that a real representative or researcher has been verified. Automated local tests use a deterministic mock and are not live inference evidence. Any pilot plans are not partnership or participant feedback.
