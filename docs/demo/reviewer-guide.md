# Reviewer guide

**Live demo:** <https://mindcommons-mozilla-demo.bepoadewale1.workers.dev/>. The demo uses fictional community records and synthetic research material. It is a technical prototype, not a community pilot or clinical product. A separate static future-product visualization is available at <https://bepoadewale.github.io/mindcommons/>; it has no API or AI execution.

The current production model setting disables Gemma reasoning. The API returns only user-facing text, excludes reasoning metadata, treats empty output as a failure, and displays the result in a readable format. Chromium verified a real synthetic inference and the production page's public video link.

Choose **Explore the demo**, switch to the fictional Community member seat, and withdraw contributor B's sample permission. Switch to Researcher and run the fixed “Community wellbeing research” evaluation: only the other eligible synthetic records are sent to the model. Switch to the fictional representative seat and approve the proposal requiring permission from everyone, then repeat the same request; the server denies it before inference. The proposal changes the decision for the identical request. **Commercial advertising** is also denied. The **Community AI Agreement (JSON)** and its schema links show the policy, researcher, contribution permissions, model restrictions and current benefit terms.

To inspect benefit accountability, the fictional community representative agrees to the accessible-summary obligation, the research seat accepts responsibility and submits a fixed fictional evidence marker, and the representative reviews it. The reviewer may request changes and the researcher can resubmit. This is a synthetic workflow; it does not claim that a benefit was delivered. **Watch the project demo** opens the public 1920×1080 MP4 hosted by the production Worker. GitHub Pages hosts the static future-vision page and is not the live backend demo.

The page identifies implemented and proposed capabilities. The demo role selector switches fictional seats in an isolated visitor session; these roles are not authenticated identities. The server-side checks demonstrate that policy and permission records affect the requested action, not that a real representative or researcher has been verified. Automated local tests use a deterministic mock and are not live inference evidence. Any pilot plans are not partnership or participant feedback.
