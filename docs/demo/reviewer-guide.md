# Reviewer guide

**Live demo:** <https://mindcommons-mozilla-demo.bepoadewale1.workers.dev/>. The demo uses fictional community records and synthetic research material. It is a technical prototype, not a community pilot or clinical product. A separate static future-product visualization is available at <https://bepoadewale.github.io/mindcommons/>; it has no API or AI execution.

The current production model setting disables Gemma reasoning and has returned visible user-facing text in a real synthetic inference. The current feature branch further limits the API response to that user-facing text, excludes reasoning metadata, and displays the result in a readable format. That response-format change still needs to pass CI and be redeployed before the final video is published.

Choose **Explore the demo**, approve the fictional proposal, switch the demo seat to Researcher, and run the fixed “Community wellbeing research” evaluation. The API checks the active policy and separate fictional individual permission, then calls Cloudflare Workers AI with a small synthetic corpus. Choose **Commercial advertising** and run again; the server denies it before model inference. Reload the page to inspect the decision in recent activity. The benefit commitment is hypothetical, with no delivery evidence claimed. The landing page includes a direct link to the project video after the video artifact is deployed.

The page identifies implemented and proposed capabilities. The demo role selector switches fictional seats in an isolated visitor session; these roles are not authenticated identities. The server-side checks demonstrate that policy and permission records affect the requested action, not that a real representative or researcher has been verified. Automated local tests use a deterministic mock and are not live inference evidence. Any pilot plans are not partnership or participant feedback.
