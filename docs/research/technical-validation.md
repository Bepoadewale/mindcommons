# Technical validation notes

Reviewed 2026-11-17. These facts are a point-in-time check; confirm limits, model availability and APIs again before deployment.

## Platform direction

- Cloudflare's current best-practices guide recommends Workers Static Assets for new static and full-stack apps. Static assets can use a same-origin Worker API and D1/Workers AI bindings without a persistent server. Pages Functions remain supported and can use the same runtime bindings, but are no longer the selected architecture here. Sources: <https://developers.cloudflare.com/workers/best-practices/workers-best-practices/> and <https://developers.cloudflare.com/pages/functions/>.
- Workers Static Assets supports SPA fallback, selective `run_worker_first`, `_headers`, and `_redirects`. Static asset matches are free and unlimited; Worker-first API requests count against Workers limits and can return 429 when free request limits are exceeded. The config routes only `/api/*` through the Worker. Sources: <https://developers.cloudflare.com/workers/static-assets/>, <https://developers.cloudflare.com/workers/static-assets/headers/>, and <https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/>.
- Wrangler is installable as a project dependency and supports local development, migrations and deployment: <https://developers.cloudflare.com/workers/wrangler/install-and-update/>. Pin the selected version in `package-lock.json`; do not assume a global CLI.
- Pages Functions are billed as Workers. The Workers Free plan currently includes 100,000 requests/day and 10 ms CPU time per invocation; static asset requests are free. A function exceeding free quotas can fail. Sources: <https://developers.cloudflare.com/pages/functions/pricing/> and <https://developers.cloudflare.com/workers/platform/limits/>.
- Workers can be deployed through an external GitHub Actions workflow using Wrangler; this avoids requiring Cloudflare's Git integration but needs a project-scoped account token in a GitHub Actions secret. That credential and workflow are not configured. Source: <https://developers.cloudflare.com/workers/ci-cd/external-cicd/github-actions/>.
- D1 Free currently includes 5 million rows read/day, 100,000 rows written/day and 5 GB total storage across databases. D1 is scale-to-zero, with no compute charge. Free limits are enforced; excess queries fail until reset. Source: <https://developers.cloudflare.com/d1/platform/pricing/> and update: <https://developers.cloudflare.com/changelog/post/2026-09-01-d1-free-tier-limit-enforcement/>.
- Workers AI currently includes 10,000 Neurons/day on Workers Free; exceeding the allowance fails unless the account has a paid plan. Some models require Workers Paid. The docs list `@cf/google/gemma-4-26b-a4b-it` among free-accessible examples. Verify the selected model and account access before use. Sources: <https://developers.cloudflare.com/workers-ai/platform/pricing/>, <https://developers.cloudflare.com/changelog/post/2026-07-28-models-require-workers-paid/>, and <https://developers.cloudflare.com/workers-ai/models/>.

The replacement candidate is `@cf/google/gemma-4-26b-a4b-it`, named by Cloudflare as a smaller-model replacement; its model page lists unit prices and does not list it among models requiring paid billing. It is not yet verified against the Cloudflare account or called live. Sources: <https://developers.cloudflare.com/changelog/post/2026-11-05-planned-model-deprecations/>, <https://developers.cloudflare.com/workers-ai/models/gemma-4-26b-a4b-it/>, and <https://developers.cloudflare.com/workers-ai/platform/pricing/>.

## Frontend and testing direction

- React, TypeScript and Vite are selected for a strict typed SPA; package versions are pinned in `package-lock.json`.
- Use a semantic HTML/CSS design system and installable PWA manifest/service worker. Cache static public assets only; never cache API responses or private narratives.
- Unit and integration tests use a mock AI binding; Wrangler local D1 tests exercise the real SQLite-compatible database path. Playwright tests cover browser journeys. A separate live call is required to claim production inference.
- Workflow permissions should default to read-only and pin third-party actions to reviewed versions or immutable revisions. GitHub Actions docs: <https://docs.github.com/actions/security-for-github-actions/security-guides/automatic-token-authentication>.
- GitHub Pages is available for public repositories on GitHub Free, and a custom Actions workflow can build and deploy a static artifact. Its Actions deployment requires `pages: write` and `id-token: write`; a separate build job needs only read permissions plus Pages read access for configuration. MindCommons uses it only for a static future-vision visualization: no API, AI, consent changes, or sensitive data are sent. It is a limited wireframe fallback, not the backend demo. Sources: <https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages>, <https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages>.
